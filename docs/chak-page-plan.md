# CHAK 문제개선보드 기반 사례 페이지

갱신일: 2026-11-16 · 문제개선보드 순서로 전면 재구성

## 현재 구성 원칙

이 문서는 이전 기획안을 대체한다. `reference/CHAK_문제개선보드.png`에 담긴 설명 순서를 따르고, 새 앱 목업 대신 제공된 기존 화면과 개선 와이어프레임을 사용한다. 상세 페이지는 `chak_case.html`이며 후속 요청에 따라 메인 `index.html#chak`에 소개 섹션을 연결했다.

각 개선 항목은 ‘문제 → 기존·개선 화면 비교 → 무엇을 왜 바꿨는가’로 설명한다.

## 본문 뒤에 배치하는 추가 자료

- 가게 QR 결제 후속 흐름: 스캔 → 금액 입력·가맹점 확인 → 결제 완료.
- 내 QR: 기존 표시 화면과 개선안 비교. 제시 행동·잔액·유효시간 설명.
- 잔액 부족: 실패 이유와 충전 이동.
- 개선 요약: 세 가지 문제와 변경 내용을 1:1 대응.
- 부록: IA·화면 명세 확대 열람, 원본 보드·표지·이력·홈 명세 링크.

## 원본과 구분할 사항

- 개선 화면은 제공 와이어프레임이다. 배너나 버튼을 임의로 다시 디자인하지 않는다.
- 보드의 하단 ‘전체 메뉴’와 홈 와이어프레임의 ‘마이페이지’ 차이를 표시한다.
- 버튼 최소화는 전체 기능 삭제와 다르다. 기능의 진입 위치와 우선순위를 설명한다.
- 환불과 결제취소를 같은 기능으로 취급하지 않는다.
- 금액과 QR 유효시간은 예시다. ‘3초’는 목표이며 측정된 성과가 아니다.

## 구현 범위

- `chak_case.html`, `css/chak-case.css`, `js/chak-case.js`만 사용한다.
- 이미지는 클릭으로 확대하고 Esc·닫기·바깥 클릭으로 종료하며 초점을 원래 버튼에 복원한다.
- 모바일의 전후 비교는 기존 → 개선 순서로 배치한다.
- 실제 QR 생성·카메라·결제 기능은 연결하지 않는다.
- 상세 페이지 스타일은 독립 유지한다. 메인 소개는 `index.html`과 `css/main.css`에 추가한다.

## 메인 소개 섹션

- 위치는 모두매쓰 다음, TRACKSY 이전이다. 기존 카테고리 정렬에서도 같은 UIUX 그룹의 순서를 유지한다.
- 모두매쓰의 제목·설명·Before/After 토글·버튼·하단 정보 항목을 재사용한다.
- 최초 버전은 모바일 기기 하나에서 기존 홈과 개선 와이어프레임을 전환한다. `versions/chak-toggle-v1.html#chak`에 해당 모습을 보존했다.
- 현재 메인은 토글 없는 v2로, 모바일 박스 두 개에 Before·After를 동시에 표시한다. 480px 이하에서는 두 화면을 세로 배치한다. PC 화면은 추가하지 않는다.
- Overview는 상세 페이지, UX Flow는 상세 페이지의 QR 안내 섹션으로 이동한다.
- 하단 항목은 Contribution·Design Color·Font Style·Generative AI·Tools Used·Duration이다. 확인하지 않은 기여율이나 앱 배포 정보를 작성하지 않는다. 제작 날짜는 사례 페이지 제작 월로 한정한다.
- 상세 페이지의 포트폴리오 복귀 버튼은 `index.html#chak`으로 연결한다.

## 가독성 점검 및 반영

기존 페이지는 본문 13~15px, 일부 메뉴·캡션 9~12px로 작았다. 모바일에서도 작은 크기가 유지되고 문제 정의의 화면 두 개를 나란히 배치해 이미지 안의 글자도 읽기 어려웠다.

- 주요 본문을 17~18px, 보조 설명을 14~16px로 키웠다. 제목과 캡션도 함께 조정했다.
- 본문 자간을 -0.025em에서 -0.012em으로 완화하고 줄 간격과 문단 여백을 확보했다.
- 보조 글자색과 장 번호를 더 진하게 조정하고 긴 설명의 줄 길이를 제한했다.
- 비교 화면은 데스크톱 245px에서 300px, 모바일 230px에서 280px 기준으로 확대했다. 좁은 화면에서는 사용 가능한 너비 안에 맞춘다.
- 문제 정의의 이미지는 별도 큰 영역으로 배치하고 모바일에서 하나씩 보여준다. 태블릿의 3개 후속 화면도 글자와 이미지가 과도하게 작아지지 않게 재배치했다.
- 이미지 확대창에 원본 크기 보기와 화면에 맞추기를 추가했다. 이미지 내부 글씨는 원본의 일부이므로 HTML 글씨 크기와 별도로 확대해야 한다.
- 모바일의 문구 전후 비교를 세로로 바꾸고 장 번호와 제목을 분리해 좁은 열의 반복 줄바꿈을 줄였다.
- 상단 목차와 버튼의 조작 영역을 늘리고 320px에서도 페이지 가로 넘침이 없게 확인했다.

남은 제약은 원본 이미지의 해상도와 이미지에 포함된 작은 글자다. 원본 크기로 열어도 흐린 글자는 더 높은 해상도의 원본이나 벡터 화면 자료로 교체하면 개선할 수 있다.
